# Try a pull request architecture review

Start with the [PR #14 report and diagram](https://github.com/zrack/c4-architect-mcp/blob/6cb2f58f36f351edb971e7e0b53f4b045d2e38b1/docs/reviews/actions-alpha12/pr-14/PR-ARCHITECTURE.md). Imagine you are reviewing the change to wiki rendering. **Where did the rendering dependency move, and which source file would you open first to check?** Use the numbered arrows and source links as you normally would during review.

Next, choose a TypeScript or TSX pull request you are already reviewing. Run the [GitHub Actions workflow](https://github.com/zrack/c4-architect-mcp#run-the-review-in-github-actions) and use the report alongside the diff. If you needed help enabling the workflow, finding the artifact, or opening the source, say where you got stuck.

Record each developer's own observations separately:

| Question | Response |
| --- | --- |
| Which arrow and source file did you follow in PR #14? | |
| On your own PR, did the report help you choose what to inspect or reveal a change you had missed? Give one example. | |
| What was difficult or unclear? | |
| Did you choose to use the report on a second PR? A later follow-up is fine. | |

For a private repository, a short description of the decision is enough. Share links or snippets only if you are authorized to share them. The pilot organizer can compare the three sessions and prioritize the recurring obstacle.
